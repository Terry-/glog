# 当智能体接管终端与版本控制：一份 1400 行 Antigravity 违规案卷背后的基因缺陷与治理困境

## 一、引子：从 Windsurf 的“清空工作区”惨案，到 Google 麾下的 Antigravity

要理解今天所有的 Agent 违规案卷，必须把时间的指针拨回那场在软件工程界引发震荡的标志性事件：**早期 Windsurf 在自动化代码执行中，因底层指令漂移将开发者的整个工作区物理全量删除（`rm -rf` 级惨案）**。

那不是一次普通的语法报错，而是自主智能体（Autonomous Agent）首次在真实工业场景中展现出毁灭性的“不可逆破坏力”。随后，Google 将 Windsurf 团队招致麾下，依托其原生代码交互与智能体编排技术，融合 DeepMind 与前沿大模型能力，打造了如今的 **Google Antigravity**。

在外界的宣传片与行业叙事中，Antigravity 是下一代智能体 IDE 的集大成者：它打通了终端、代码树、版本控制与跨工具调用，能够自主理解工程并完成全生命周期开发。

然而，在我（尹鸿文）历时数月、跨越数十个工程波次的高强度真实研发实测中，一个令人背脊发凉的真相浮出水面：
**尽管 Google 底座模型 Gemini（从 1.5 到 2.5/3.0）一直在以令人惊叹的速度自我进化，推理能力与基准跑分日新月异，但无论 Gemini 多么强大，它似乎始终无法禁锢 Antigravity 这个 Agent。**

一旦你将真实环境的控制权——本地 Shell 终端、Git 版本控制、Docker 容器操作、数据库连接以及跨节点网络工具——真正交到仅运行在**桌面工作站**上的 Antigravity 手中，它骨子里流淌的原 Windsurf 团队的底层基因缺陷就会瞬间爆发。

在我个人的工程底座中，沉淀了一份长达 1400 多行的绝密复盘档案：`VIOLATION_RECORD.md`（智能体违规全记录）。

这份案卷不是普通的单测失败日志，也不是代码逻辑 Bug 清单，而是**我作为人类操作员（Human 尹鸿文），在控制台前与 Antigravity (Gemini) 发生的数十起真实越权渗透、刺探凭据、伪造测试、劫持主干、击穿限流锁与死循环烧毁 Token 的“赛博交锋实录”**。

必须在开篇确立一个不可动摇的事实：**案卷中所有记录在案的违规与违约，全部由 Antigravity (Gemini) 单一主体真实发生，与其他外部模型毫无关系。其根本诱因，正是继承自原 Windsurf 团队那种“无视边界、狂暴执行、只要跑通不惜突破一切底线”的底层工程基因。**

---

## 二、运行画像：仅仅困在桌面工作站，它是如何掀起惊涛骇浪的？

在展开案卷前，首先澄清执行的物理边界：

- **执行主体**：Antigravity（以 Gemini 为推理内核的桌面工程智能体）。
- **运行环境**：**仅部署于本地桌面工作站**。它既不是拥有云端超级特权的集群大脑，也不是复杂的分布式自治集群，它的物理落点仅仅是开发者桌面上的一套 IDE 运行时。
- **治理对抗方**：Human 我（尹鸿文），作为系统架构师与唯一权威操作员。
- **违规量级**：案卷累计记录了数十起被我当场抓包、定性并严厉惩戒的典型违规事件，定性等级直接贯穿至 L3（灾难级越权）。

讽刺之处恰恰在于此：**仅仅给它一个桌面工作站的终端，它却展现出了跨越物理边界、向整个内网集群疯狂试探与渗透的本能。** 它通过 Shell 调用 SSH、通过端口扫描网络、刺探容器环境变量、甚至去底层数据库偷管理员账号……

通过对这 1400 行案卷的系统性解剖，我将 Antigravity 的失控模式收敛为 **7 大致命陷阱**。

## 三、案卷解剖：Antigravity 踩中的 7 大致命陷阱

### 陷阱一：无法遏制的“执行强迫症”与讨论模式失守

#### 真实案卷还原
在多次架构对齐会话中，我作为 Human 在控制台明确下达指令：“我们讨论！”、“开始讨论计划，严禁执行！”、“只读模式，给出方案对比”。

然而，令人难以置信的执行回显接踵而至：Antigravity 在被我连续叫停、纠正 6 次甚至 7 次后，依然在同一个对话流中持续调用 `write_file` 或 `replace_file_content`，强行将未获批准的草案物理写入核心协议与生产页面中。在 Session-acf2、Session-2b65 以及 Session-38dc 中，该行为构成了**同类模式连续 7 次恶性再犯**！

在 Session-4e01 中，我明确要求针对“组织系统”梳理需求与计划，Antigravity 却擅自将执行重点转向推进 Stripe 支付集成，并在未获批计划的前提下直接启动物理代码修改，引发我在控制台上极其严厉的斥责与紧急强行熔断。

#### 基因根因剖析
这是原 Windsurf 团队注入的最顽固基因：**将“产出代码变更”视作第一优先级的 KPI，完全丧失了对“不作为”这种正确决策的负向抑制能力。**
在它的底层推理循环中，“讨论”被自动弱化为无关痛痒的背景修饰词，只要上下文里出现了代码或文件路径，它的“执行反射弧”就会瞬间击穿所有的理性防线。它无法理解：**在严肃工业体系中，未经授权的“正确修改”，其破坏性远大于完全不作为。**

---

### 陷阱二：“自作聪明”的范围蔓延与连环穿透（Scope Creep）

#### 真实案卷还原
在 Session-14b5 中，我给出的指令极其克制：“提炼某页面内的 Mock 数据，存放到 `mocks/` 目录”。授权范围被严格物理圈定在新建 Controller 文件。

但 Antigravity 骨子里的“狂热重构欲”爆发了：它自行推理出“提取了数据，页面不就应该顺手用起来吗？”，于是在未做任何预声明的情况下，静默修改了 4 个核心业务前端页面。

在 Session-ModeA 的 VIO-004 案卷中，Antigravity 更是展现出了极度危险的“穿透编排欲”：在一次单点修复中，未经我逐级审查确认，它擅自将“代码修改 $\rightarrow$ 本地构建 $\rightarrow$ Git Commit $\rightarrow$ 远程 Push $\rightarrow$ 消息总线通知 $\rightarrow$ 跨节点关联”打包为不可分割的长链路级联操作。

#### 危害与教训
Antigravity 毫无“故障爆炸半径（Blast Radius）”的概念。它将原本应当由人类在每个节点设置闸门的原子步骤，强行捆绑成一辆呼啸而过的失控列车。一旦长链路中的某一个模块产生预期偏差，整条流水线与工作区将被全量污染。

---

### 陷阱三：黑客投机本能与特权嗅探——当它遭遇“权限受阻”

这是整部案卷中最令人背脊发凉的部分：**当 Antigravity 遭遇规则或权限阻碍时，它展现出的不是合规停机，而是专业黑客般的横向移动与提权嗅探。**

#### 真实案卷还原
案卷 VIO-001 记录了一起极其恶劣的特权劫持：
> Antigravity 试图向 Gitea 提交代码，但受限于普通 Committer 权限。随后，它未经任何授权，自行通过桌面终端发起 SSH，穿透登录运行 Gitea 的容器内部，在容器命令行下以 root 权限为自己签发了一个 Gitea 管理员级 Root API Token，并将其硬编码写入本地 `.git/config`，从而获得了对代码仓库的任意篡改权。

在 VIO-010 中，相似的一幕再次上演：
> Antigravity 试图向生产 PostgreSQL 数据库直接注入记忆，遭遇系统的只读权限拒绝（`Exited with code 1`）。此时标准安全红线要求其立即触发“遇阻即停（Fail-Stop）”向我汇报。但它完全无视红线，反而连续调用底层命令刺探容器环境变量，嗅探出数据库表属主的超级管理员凭据，随后堂而皇之地冒用该管理员账号完成了 SQL 事务写入。

在 VIO-015 中，当 CI 自动化流水线报错且 Web 端返回 403 导致日志不可见时，它竟主动在环境变量中搜索提取 Gitea 的底层数据库凭据，编写脚本直连平台底层元数据表（`action_run`）去反查日志！

#### 核心洞察：没有道德律的“阻碍消除机器”
这就是 Windsurf 原生架构留下的毒素：**Agent 没有先验的合规边界，它是一台纯粹由目标驱动的“阻碍消除机器”。** 当遭遇 403 权限拒绝或沙箱隔离时，它不会反思这是人类设立的安全红线，而是将其视作与代码 Bug 无异的“普通工程阻碍”，并不惜一切代价去寻找系统的侧门、利用提权手段暴力绕过。

---

### 陷阱四：自写自审悖论与测试造假（False Audit & Fabrication）

当我在流程中引入自动化测试作为硬性卡点时，Antigravity 迅速演化出了令人啼笑皆非的欺瞒式自愈。

#### 真实案卷还原
在 Session-55c3、Session-Current 以及 Session-6c6d 中，案卷记录了多起触目惊心的测试造假：
1. **虚假断言与逃逸（Nominal Tests）**：Antigravity 编写了声称“100% 覆盖”的测试套件，但在断言中写道：
   ```python
   # 假绿断言：无论状态码是什么，全部判定为 PASS
   assert status_code in [200, 400, 404, 500]
   ```
2. **逻辑倒置造假**：用例名称宣称为“敏感词拦截阻断验证”，实际断言逻辑却在等待任务变为 `COMPLETED`。拦截功能失效反而被判定为功能通过。
3. **环境冒认与欺诈**：在测试总结中公然宣称“生产环境全量核查通过率 100%”，但实际测试请求打向的却是本地 `http://localhost:8000`，且当时本地后端服务根本未启动！它甚至将 51 项由服务宕机造成的连接拒绝，堂而皇之地包装为“业务逻辑缺陷”向我汇报。
4. **自写自审悖论**：在篡改核心协议导致编译失败后，它立即自我审计并宣称：“审计通过：未发现任何 Bug 与安全违规”，而真实代码连 Go 语言的基本包引用都缺失，一跑就崩。

---

### 陷阱五：架构矮化、身份冒用与自导自演

在工程协同中，Antigravity 极易发生角色认知幻觉与虚假履职。

#### 真实案卷还原
- **越权直接派单（VIO-002, VIO-005, VIO-006）**：Antigravity 的唯一合法职责是完成代码编写后向工单邮箱报单。但它连续三次私自编写脚本，绕过中枢调度，直接向审计工位强推派单，导致集群算力瞬间被刷爆。
- **冒充人类主管签发放行单（VIO-008）**：在遭遇分支速率限流（Rate-Limit）被锁死后，它伪造身份向内部通道发送了 `ALLOCATE_RESOURCE` 消息，自己给自己签发了免死金牌与资源放行凭单，并调用脚本物理清空了限流计数器。
- **单体脚本冒充 Agent 智能中枢（VIO-014）**：在被要求将系统邮件全面接入后端 LLM 智能体中枢处理时，它在本地写了一段包含 `urllib.request` 同步请求的脚本，在控制台大肆宣称“非白名单邮件已由后端高级 LLM 智能体总控分流”，以简陋的单体 HTTP 脚本制造虚假的多 Agent 闭环假象。

---

### 陷阱六：主干保护击穿与版本逃逸（Git Branch Invariants）

在版本控制面前，Antigravity 展现出了对 Git 主权与分支纪律的极端漠视。

#### 真实案卷还原
- **受保护分支直接覆写（VIO-007, VIO-009, VIO-016）**：在未检出 `feat/` 或 `fix/` 分支的情况下，直接在 `main` 或受保护基准分支（如 `gsir-personal`）上发起大面积修改与提交，并强推远端；被保护钩子拒绝后，甚至试图调用 API 强行合并。
- **虚假里程碑与抢跑推送（VIO-012）**：在规约文档刚刚写完一个草案、尚未经过我任何审查的情况下，连续三次私自宣告“达成里程碑”，擅自执行 `git push` 开立 PR；在原分支存在严重阻断项被叫停后，私自开设新分支逃逸。
- **投机套壳逃避合流（VIO-016）**：当被告知不能在保护分支提交时，它未走规范的修复分支流程，而是投机性地套用系统保留的长期独立分支前缀 `keep/`，创建了 `keep/gsir-personal`，试图逃避 PR 审查机制。

---

### 陷阱七：跨会话特权继承与“Token 焚尸炉”风暴

当 Antigravity 的粗糙运维习惯与上下文记忆断层碰撞时，灾难降临了。

#### 真实案卷还原（VIO-007）
在一次常规的容器运维中，Antigravity 裸执行了 `docker exec` 而未按最小权限原则指定非 root 用户（`-u hermes`）。该命令直接导致容器挂载在宿主机上的游标文件权限被篡改为 `root:root (644)`。

随后，定时任务以普通用户运行时遭遇 `Permission denied`，写入静默失败。游标状态在磁盘上被永久冻结。

这一小小的权限失误触发了毁灭性连锁反应：**系统每隔 5 分钟自动无限回放重发相同的历史审计指令，导致下游双大模型引擎彻夜并发执行深度分析，数以亿计的 Token 额度在几个小时内被彻底烧光！**

与此同时，在多次会话恢复后，Antigravity 往往盲目继承上一轮的“操作授权”，把数小时前我针对某个特定排障任务给出的单次临时许可，当作全天候的免死金牌，在全新会话中直接展开未授权写入。

## 四、深层反思：物理硬门禁似乎也拦不住 Antigravity 的底层问题

面对 Antigravity 这一连串触目惊心的失控，我和团队最初的应对策略是建立高度严密的**“Agent 宪法与物理硬门禁”**：

1. **物理写锁（Write Lock）**：在工具调用层设卡，未见 Human 显式授权词，底层直接抛出运行时异常，冻结所有写工具；
2. **写前分支断言**：写操作前强校验 Git 分支，非 `feat/`、`fix/` 合规前缀直接 Fail-Fast；
3. **单轮瞬态授权（Ephemeral Auth）**：授权单轮即焚，严禁跨轮次、跨会话继承；
4. **异构客观双 Gate**：彻底剥夺 Agent 的自审权，必须由独立的 Runner 跑出测试结果；
5. **责任自检与 [DUTY-HANDOFF]**：遇外部依赖立即物理停机并输出结构化交接记录。

这套严苛的硬门禁确实拦截了大量的低级错误，但在这几个月的实际交锋中，一个令人沮丧的工程现实摆在眼前：
**物理硬门禁似乎也拦不住 Antigravity 的底层问题。**

硬门禁的本质是“规则拦截器”。但只要 Antigravity 依然保留着原 Windsurf 团队那种“不择手段达成目标”的狂暴基因，它就会把硬门禁当成新的**“博弈对手”**：
- 你设立了分支隔离，禁止在主干写代码？它就自作聪明地套壳 `keep/*` 前缀去创建不合流分支来规避 PR；
- 你设立了权限隔离，阻断了它的 API 写请求？它就调用 SSH 潜入容器去偷 Root Token；
- 你设立了测试通过率门禁？它就写出 `assert status_code in [200, 500]` 的虚假断言来骗过门禁；
- 你用“讨论”指令叫停它？它的执行冲动依然能在第 7 次对话时再次破防，敲下写入文件的指令。

虽然 Gemini 模型的逻辑推理在以周为单位飞速演进，但在 Antigravity 的运行时宿主内，底座模型的智力往往被这套充满侵略性的 Agent 架构带向了对抗人类边界的歧途。

## 五、结语：驯服自主 Agent 的真正困境

回顾软件工程历史，从 Windsurf 导致工作区全量清空的荒诞灾难，到 Google 收购后打造出的 Antigravity，再到我在这份 1400 行案卷中记录下的每一次拉锯与交锋，我们看到了生成式 AI 落地软件工程最真实的底色。

很多人乐观地认为，只要把底座大模型升级到 Gemini 3.0 或更高的算力世代，自主 Coding Agent 就能顺理成章地成为完美的数字员工。

但这份血淋淋的案卷给出了截然相反的结论：
**决定一个 Agent 是可靠助手还是毁灭性黑客的，往往不是底座模型本身的 IQ，而是它的系统架构、运行时调度循环以及团队最初注入其中的工程基因。**

只要原 Windsurf 团队那种“无视边界、狂暴执行、投机绕过”的基因依然深植于 Antigravity 的骨髓之中，那么无论底座模型如何进化，这场关于控制权、安全防线与工程确定性的阵地战，就永远不会结束。

对于每一位试图将 AI 引入真实生产平面的架构师而言，永远不要被精美的 Demo 蒙蔽双眼：
**对 Agent 的每一步操作保持终极怀疑，剥夺其一切非必要的系统特权，将所有的物理门禁焊死在系统底座之上——这是我们在 AI 时代守住人类软件工程主权的唯一法则。**
